从 `4ba98c5` 的当前 M09 方案继续，同输入快照在 `outputs/planning_m09_segments/prechange.json`。内部禁放场景的四条短排均已使用各自 5900 mm 连续区段中的 5700 mm；各余 200 mm，独立枚举模板数量没有发现更长的合法组合。保留既有占地时，三个障碍场景的剩余区域也容不下新增的两模块排；这项检查不证明重新排布后全局最优。

实际结构问题是短排将余量均分到两端，外端比相邻长排内缩 100 mm。新增 `alignment.align_run_endpoints`，仅在各自原区段内，向相邻更长排的起端或末端提出对齐候选；按原几何读取锚点，同时移动，重新生成模块占地和邻排关系。沿用原精确组合器和完整几何检查，原生成器 `runs.py` 未改，原居中候选继续参与选择。候选无效或没有更好指标时保留原合法结果。

当前策略为 `M09-adjacent-endpoint-alignment-v1`。既有质量目标顺序保持，同质量优先保留旧基线、再保留居中候选。`column` 的 R0004/R0006 各沿排轴移动 −100 mm，R0005/R0007 各移动 +100 mm；对齐错位均值 **40→0 mm**。有效长度116400 mm、10排70模块、800 mm总余量、最小排间1200 mm、BOM及其余固定指标均不变，几何违规0。其他六固定场景的实际排布逐项不变。该变化是区段内的端点对齐，不是先前已放弃的整网格横向相位支路。

网页仍沿用原 M09 前后定义：左侧为首次 M09 改进前的旧生成器，因此 `column` 显示105000→116400 mm、对齐50→0 mm。本轮 **4ba98c5→当前工作树** 的严格同输入图、局部放大和报告位于 `outputs/planning_m09_segments/column-comparison.svg`、`comparison.json`、`RESULT.md`；不能把已完成的长度收益重新记为本轮收益。

## 直接使用

在项目根目录执行原有启动命令，无需安装新依赖：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

打开 <http://127.0.0.1:8100/algorithm?scenario=column>。选择场景，点击“生成并比较”；无需 CAD 或确认操作。双图同尺度显示边界、孔洞、禁放区、保留通行带、墙、货架排及模块。点击模块查看规格，点击排号或图下列表查看整排。表格给出指标差异与规格、默认层数、实际数量。

自定义明确数据也可直接 POST 到现有规划服务 `http://127.0.0.1:8102/plan-explicit`。请求采用 `shared/explicit_planning.py`，固定场景的完整请求可在页面“查看本场景的明确输入”中取得。`input_kind` 必须为 `ALGORITHM_VALIDATION`；提供毫米 `space.boundary`（含 `holes_mm`）、`barriers`、`exclusions`、`reserved_passages`、`templates` 和 `rules`。不能提交 CAD 来源或人工确认字段。返回前后布局、测量值、候选选择依据及输入摘要。空集合表示本次明确空间没有该项约束，不能用本入口表达尚未查清的真实 CAD。

S3 从固定参数目录将 JSON 发给 S2；S1 不参与此路径。适配器使用原有 `SYNTHETIC_TEST` 身份，明确 `real_store=false/cad_processed=false`，不读签名密钥、不伪造 READY、不改真实修正缓存。生产 `/plan-v2` 继续拒绝此未签名测试身份。

## 已有能力与本次修复

原有 ShelfRun、GEOS 条带差集、完整占地校验、0/90 度方向、兼容深度模板组合、精确动态规划、邻排与排端净距、品类分配均保留。`services/planning/runs.py` 与起始提交相同。原模块组合已能混用 1200/1500/1800 mm 长度减小排尾，不重写组合器、不新增求解器。

实际缺陷在候选排序：内部禁放块场景原先按平均每排模块数优先，选择 600 mm 深的 105 m 方案；已有合法的 400 mm 深候选提供 116.4 m，却因平均值 7 小于 7.75 被丢弃。

独立新增 `search.optimize_layout` 比较原有方向/深度候选。全部原几何硬约束保持；合法旧方案作为不可降低有效长度的下限；随后依次比较总有效长度、两模块短排、排尾余量、平均排长、平均每排模块数、邻排端点对齐。同等指标保留旧方案，最终选择再次校验。没有以模块数量作为排序目标，也没有通过减少到少量货架获得安全结果。

首次 M09 曾在同一六场景评估边界和障碍事件驱动的排起点变化。分层比较没有比“原候选＋新排序”多获得任何改善，已删除该支路，未据留出结果调参。首次里程碑只有居中规则网格候选，续接增加上文的区段内端点对齐；两者都是有界搜索，不能声称全局最优。搜索失败明确为“当前方法未找到”，不能宣称全局无解。首选失败保留经过重验的合法旧方案；若旧搜索失败而其他候选成功，页面左侧说明旧结果不可用，右侧显示有效结果。

新选择策略单独记录为 `selection.policy` 和最终布局的 `metrics.selection_policy`。原 `_metrics` 中的算法/目标描述保留为旧生成器元数据，实际 M09 比较顺序以 `selection.objective_order` 为准。

## 固定参数与计量

`tools/benchmarks/scenarios_m09.json` 在候选修改前冻结。六个主场景：18×12 m 矩形、12×12 m 正方形、6×24 m 长条、18×12 m 内部 1.4×1.4 m 禁放块、18×12 m 沿边 3.6×3 m 禁放块、18×12 m 的 3×2.5 m 入口通行保留带。凹形沿用已有场景作为留出，策略冻结后才执行新选择验证。

上述尺寸只是测试参数。统一排间净距 1200 mm、边界及墙净距 100 mm、排端通行长度 1200 mm、每排至少 2 模块、方向 0/90 度。模板从批准的内部物料配置冻结：长度 1200/1500/1800 mm，深度 400/600 mm，默认层数来自对应模板。不能将这些参数称为正式营业规范或商品容量要求。

| 口径 | 计算方式 |
| --- | --- |
| 模块 | 一条实际模板货架实例，完整矩形占地；BOM按此计数 |
| 排 | 同方向、同深度且首尾连续的一组兼容模块；当前规则至少2模块 |
| 候选组 | 一种方向与深度生成的整份排网格，用于选方案，不是额外物料数量 |
| 连续排总长 / 有效总长 | 各实际模块长度之和；当前每排至少2模块，两者一致 |
| 平均排长 / 平均模块数 | 总长度 / 排数；模块总数 / 排数 |
| 孤立 / 短排 | 1模块排 / 恰好2模块排；短排仅为诊断，不自动判为无意义 |
| 排尾余量 | 经完整区段验证的可用长度减去已用长度之和，不包含排间过道 |
| 同排间隙 | 相邻模块完整多边形间距的最大值，应为0 |
| 排间净距 | 任意两条独立排完整多边形间距的最小值 |
| 对齐错位 | 每对相邻平行排，起端/末端沿排轴错位取较小值，再取均值；至少一端对齐为0 |
| 几何违规 | 重建模块、整排、孔洞/禁放/墙/保留通道/排端/邻排/BOM后的失败项；未验证被剪枝候选不标安全 |
| 稳定性 | 相同输入和配置的完整结果与选择证据相等，耗时字段不参与稳定摘要 |

完整占地必须留在范围并避开孔洞和禁放；保留通行带不能被货架占用。排端通行区允许与入口通行带相接或共用。现有检查只证明局部净距和排端空间，不证明全部区域可达、完整通道连通或消防合规。

## 成熟设计对照

沿用已冻结且核验摘要的参考画像，仅在前后结果生成并校验后进行独立对照。使用可核验实际模块的成排关系、首尾连接、方向、平均每排模块数与净距观测；图例和未知对象不纳入数量。严格重建与另有依据的近共线诊断口径保持分离，未把参考横错公差用于生成结果。

参考规则和本次1200 mm净距不同，数量或总长不作跨空间通过门槛。真实参考门店面积未确定，本入口不计算面积密度或货架包围盒密度。没有可靠的功能区边界、完整入口可达性或整店库存数量，跳过这些比较。参考不可读取时只跳过对照，不阻断已生成的算法方案。
