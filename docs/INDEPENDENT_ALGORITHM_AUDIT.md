# 独立算法审计 · M01 / M01b

审计日期：2026-09-08。审计角色仅修改 `tests/audit_v2/` 与本文件，不修改生产实现，不进行 Git 操作。

审计对象为 `services/planning/runs.py`、`shared/planning_v2.py` 和现有 `tests/planning_v2/`。这是无障碍矩形算法审计，不是产品完成验收。

## 审计方法

- 使用独立构造的合成目录与 PlanningSpace，不读取正式 CAD、商品文件或任何成熟参考资料。
- 额外矩形覆盖最小可用跨度、非整数尺寸、长宽互换、大幅平移及约 10^9 mm 坐标；用 GEOS 对实际模块轮廓独立检查范围、重叠、连续接口和排间净距。
- 使用 `Fraction` 有理数穷举全部可行模块数量组合，与 DP 的剩余长度、模块数量和确定性 ID 顺序比较；包括小数长度、重复长度不同 ID 和不同最小模块数。
- 从合法输出的 JSON 副本进行恶意篡改，测试验证器是否重新建立几何、模板、BOM、来源和质量指标之间的一致性。
- 对 `runs.py` 执行 AST 审计，检查直接 I/O、文件读取、动态执行、参考路径和参考模块依赖。这不构成对传递依赖或未来生产 HTTP 入口的全量隔离证明。

```powershell
.\.venv\Scripts\python.exe -B -m pytest tests/audit_v2 -q -o addopts='-p no:cacheprovider --import-mode=importlib'
```

结果：**19 passed，3 failed**。失败均属于同一个主要缺陷：独立验证器接受不真实的质量及邻排元数据。

1. 将 `effective_length_mm` 改为 10^12 mm，`validate_runs()` 仍返回 PASS。
2. 将 `footprint_density` 改为 0.99，`validate_runs()` 仍返回 PASS。

物理几何仍合法不能抵消该缺陷：后续成熟设计质量 Gate 和 2D 对照依赖有效长度、密度与排间关系，错误元数据可能使不成熟布局被错误验收。修复应从实际模块轮廓独立重算并核对这些数据，不能信任客户端指标或仅验证自报哈希。
