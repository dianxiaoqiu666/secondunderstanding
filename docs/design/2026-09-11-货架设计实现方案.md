建议以现有连续排、单面/背靠背组合及路线校验代码为基础，先建立可独立运行的二维设计流程，再接入真实 CAD 和作业数据。当前最主要的缺口是输入契约、运行与交付能力，以及实验算法进入正式流程的条件。

## 3. 建议的设计流程

```mermaid
flowchart LR
    A[CAD 理解结果与来源证据] --> B[输入适配和就绪检查]
    T[货架模板与设计规则] --> B
    B --> C[连续排或作业候选生成]
    C --> D[几何与适用的路线独立校验]
    D --> E[二维方案与指标比较]
    E --> F[版本保存与清单导出]
    E -->|调整参数| T
```

**输入适配。** 建议在本项目增加纯数据适配模块，读取完整 CAD JSON 或通过受信任的 S1 结果接口取包，不在货架规划器内重新读取 DWG/DXF，也不跨目录导入上游 Python 模块。

| 输入事实 | 规划用途 | 必须处理的边界 |
|---|---|---|
| 来源 SHA256、结果标识、几何摘要、坐标系 | 绑定本次设计 | 全程毫米；图元、区域与源文件必须一致，保存具体区域视图 |
| 室内区域及其孔洞 | `PlanningSpace.boundary` | 首版支持一个明确选定区域；多区域要明确选择或返回不支持，不能自动取最大块 |
| 障碍多边形 | 禁放占地 | 保留孔洞和全部相关构件来源，不能漏掉未知语义但已知占地的对象 |
| 线状障碍 | 不可跨越线 | 拆成有来源关联的线段；厚度或占地未知不能静默当作零厚度安全障碍 |
| 门口、预留通道 | 禁摆放与通行约束 | 区分实体障碍和可以行走的预留空间；范围边界不等于实体外墙 |
| 实体墙段及明确内向 | 沿墙架依据 | 无依据时不生成沿墙架，不根据场地轮廓自动推断 |
| 模板、规则与业务来源 | 模块组合和清单 | 实际尺寸缺失要列出；默认层数保留为规划参数 |

自动设计要求采用的区域为 `READY`、允许摆放、来源匹配且无未解决的关键空间事实。`REVIEW_REQUIRED`、`NOT_READY`、`EMPTY` 和模型候选要保留各自含义，不能改写为已确认生产输入。上游页面可能展示解释后的区域，适配器必须标明采用原始 `usable_area` 还是解释视图，不能因为预览更完整而升级可信状态。

还有一项容易导致过度留白的接入问题：上游可用区域和障碍多边形可能已经计入退让，本项目会再次计算退让。首版应约定交接未施加额外业务退让的几何事实，由规划侧统一施加规则；若输入已经施加退让而无法无损还原，应明确报告并选择有完整证据的交接方式。不要把裁剪后的净可用区域直接当成原始室内边界反复收缩。依据：[上游退让计算](C:/D/汉斯/CADunderstanding/services/understanding/usable_area.py:161)、[规划安全区域](C:/D/汉斯/secondunderstand/services/planning/runs.py:159)。

**受信任的数据交接。** 纯适配器只生成待接纳的标准数据，不能把浏览器上传的 `READY` 字段当成验签依据。正式接入需要明确 S1/统一签发组件的职责：完成来源与事实校验，绑定选定区域、业务和最终规则，再签发兼容请求；S2 保留独立验签和几何重算。密钥通过运行配置交接，前端不持有。上游配套改动应拆成独立工作包。

**算法分两步接入。** 首步将 `optimize_layout` 用于经过接纳的二维连续排请求，保留旧候选并输出选择依据。第二步将单面/背靠背和可达性能力接入真实数据流程。沿用现有 Python、FastAPI、Pydantic、Shapely、NumPy 和 NetworkX 代码，首版不需要更换求解器。

M11 的生产接入需要新增版本化的真实作业事实契约。当前 `WorkPoint`、`OperationsDemand`、结构假设及部分取货面字段只允许测试来源，不能靠把标记替换成“真实”完成接入。应把候选生成、几何校验、逐面可达与具体任务评价拆开：有真实入口和取货面信息即可验证可达性；真实订单/补货任务未提供时，将任务效果标为“未评价”，不伪造任务来满足旧实验契约。依据：[作业输入](C:/D/汉斯/secondunderstand/shared/operations_planning.py:20)。

连续排结果继续使用 `validate_runs`。背靠背结果应使用 `validate_operations_geometry` 和路线证据复算：前者把“组合”作为相互净距的对象，而旧校验器要求所有不同排之间留通道，不能拿旧校验器直接校验背靠背内部两排。共同的输出封装可以统一，几何判定不能混用。依据：[连续排校验](C:/D/汉斯/secondunderstand/services/planning/runs.py:304)、[组合校验](C:/D/汉斯/secondunderstand/services/planning/operations_layouts.py:482)。

**二维操作界面。** 建议首版由现有 FastAPI 服务提供轻量页面，用 SVG 展示毫米几何。用户流程为“载入空间 → 选模板与规则 → 生成 → 比较 → 保存/导出”。画布展示范围、孔洞、障碍、门口、货架编号、取货方向及通道；选中一排查看规格、长度和余量。页面显示货架数量、有效取货面长、净距，以及适用时的路线和不可达原因。

首版通过参数调整后重新生成方案。手动移动、增删和锁定货架作为后续交互工作包，提交修改后由服务端重建占地、邻接、指标和清单，再走相应校验；前端不能提交自称 PASS 的证据。CAD 坐标与屏幕坐标的转换仅用于显示，不能回写源坐标。

**结果与清单。** 每次设计保存独立版本，绑定源文件摘要、选定区域与几何摘要、模板/规则摘要、算法版本及完整输出摘要。输入变化后原结果保留，但不能当作当前输入的有效结果。优先导出 JSON、二维 SVG 和规格数量 CSV，后续再增加 CAD 图层输出、三维和采购级清单。
